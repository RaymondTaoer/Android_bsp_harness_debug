# 原理图 PDF → 结构重建（算法与实测）

`harness/lib/pdf_schematic.py`（入口 `pdf2md --schematic`）从**矢量**原理图 PDF 里
重建候选连接关系。本文记录算法依据、实测数据与已知残留问题，供后续调参与判断
"哪些结论可以直接用、哪些必须回原图"。

## 1. 问题边界

PDF 里没有"网络"这个概念，只有三样东西：

| 元素 | PDF 里的形态 | 能否可靠取得 |
|---|---|---|
| 网络名 / 位号 / 引脚号 / 元件值 | 文字层（`get_text`） | **能**，只要不是扫描件 |
| 导线 | 矢量线段（`get_drawings` 的 `l` / 细长 `re`） | 能取到线段，但符号图形也是线段 |
| 连接关系 | 不存在，只存在于线段与文字的几何位置关系里 | **只能推断** |

所以：**文字 100% 可信；连接关系是候选**。任何声称"从 PDF 导出网表"的工具都在
做同一件几何推断，差别只在规则定得多细。

## 2. 算法（七步，每条规则都有实测依据）

1. **取线段**：`l` 直接取；`re` 里极小的方块当结点标记，细长矩形取中心线（CAD 常把
   导线画成填充矩形）；曲线只把小圆当结点标记。
2. **剔除图框与标题栏**：找占页面一半以上面积的最大矩形作图框，剔除贴其四边、贴内框
   12pt 内、以及右下角标题栏区域内的线段。
   *依据*：DL-DIS121C-V2 第 15 页，图框 + 标题栏的表格线把 6 条互不相干的信号并成
   一个 120 线段的假网络。
3. **端点吸附**：端点按 `--tol`（默认 2.0pt）量化到网格，同格即同点。
4. **夹角过滤**：同一节点上两条线夹角在 **25°~65°** 且没有结点标记 → 不合并。
   *依据*：该图 22 页端点相接的线对夹角分布为 0–9°(66 对)、40–49°(52 对)、
   80–89°(72 对)。原理图导线只走 0°（直延）和 90°（拐角/丁字），40–49° 那 52 对全是
   接插件菱形符号、二极管符号的美术线条。
5. **丁字连接必须有结点标记**：端点落在另一条线中段（距两端都 > tol）时，只有结点标记
   半径 3pt 内才认。
   *依据*：同图第 1 页 U1003 第 8 脚与 R1015 的丁字连接画了黑点；相反，无点却相接的
   情况全部是"端点恰好压在无关长线中段"。
6. **文字分类**：网络名（含下划线的大写）/ 电源名 / 低置信名（大写无下划线）/ 引脚号 /
   位号 / 元件值 / 其它。分类决定它能不能给网络命名——引脚号和元件值不许当网名。
7. **标签归属**：文字挂到 `--label-tol`（默认 6pt）内最近的线段，并对"位于文字下方"的
   线段给 0.8pt 评分优惠（Altium 默认把网标放在导线上方 2~4pt）。挂不上的网名进
   「孤立网络名」，不静默丢弃。

另有两道防噪声规则：

- **隐藏属性文字过滤**：Altium 导出会叠一层等宽字体（monospaced）隐藏文字
  （`PI<位号><引脚>`、`NL<网络名>`），且字体子集把 `_` 映射成 `0`（`NLRK0CAN10TX`）。
  判据：等宽字体且字号 < 本页主字号 95%，或字号 < 主字号 50%。该图 22 页共过滤 9300 条。
- **不猜字符串**：所有分类都基于字符形态与字体属性，不针对某块板子写死。

## 3. 实测（DL-DIS121C-V2，22 页 A3，Altium 导出）

| 指标 | 改进前 | 改进后 |
|---|---:|---:|
| 线段 / 结点 / 文字 | 16144 / 1179 / — | 16144 / 1179 / 9300 条隐藏文字被滤除 |
| 连通网络 | 2386 | 6501 |
| 具名网络 | 1621（含乱码令牌） | 862 净片段 = **228 个唯一网名**，另有 10 冲突 + 313 仅低置信名 |
| 假短路（同分量 ≥2 网名） | 45 | **10（占具名 1.2%）** |
| 被夹角规则拦下的符号图形接触 | — | 5738 处 |
| 耗时 | 9.8s | 7.8s |

**逐点真值核对**（回原图读引脚名后比对，U1003 = TJA1051T）：

| 原图 | 工具输出 | 结论 |
|---|---|---|
| pin1 `D` ← `RK_CAN1_TX` | `RK_CAN1_TX · 引脚 1` | ✅ |
| pin4 `R` ← `RK_CAN1_RX` | `RK_CAN1_RX · 引脚 4` | ✅ |
| pin3 `VCC` ← `VCC5V0_SYS` | 电源端口是填充多边形，无线段 → 进「孤立网络名」 | ⚠️ 名字有效，未算出归属 |
| 第 15 页 6 条 `4G_*` 信号各自独立 | 6 条独立，引脚 7/1/8/2/5/6 全对 | ✅ |
| 第 4 页 `4G_EN`(pin96) / `4G_RST`(pin97) 相邻 7pt | 分成两个网络，引脚号正确 | ✅（改进前被并成一条） |

## 4. 已知残留：10 个冲突网络

全部落在「冲突」栏，产物里明确标注"不能当作短路结论"。成因分三类：

| 类型 | 案例 | 成因 |
|---|---|---|
| 连接器/线束符号把相邻信号画在一处 | `CTL_DOH1..8`、`ST_DOH1..8` | 符号图形与导线同坐标，角度又不落在过滤带内 |
| 相邻 TX/RX 对 | `RX_DEBUG`/`TX_DEBUG`、`STM_UART1_RX`/`TX`、`I2C2_SCL_TP`/`SDA_TP`、`TP_INT`/`TP_RST` | 同上，多为排针符号 |
| ESD 阵列引脚 | `4G_DTR`/`4G_UART1_RX` | 阵列符号内部连线把两脚画通 |

`PWR_4G_EN_RK`/`PWR_4G_EN_ST` 属于设计上可能真同网（RK 侧 / 模组侧经 0Ω 相连）的
情况，两种解释都成立——这正是必须回原图的原因。

**为什么不再加规则去拆**：继续收紧（例如"平行且间距 <8pt 不合并"）会把正确的
分支也拆掉，反而制造漏连。当前策略是"宁可在冲突栏里显式暴露，不静默下结论"。

## 5. 用法

```bash
# 矢量化原理图
bash features/.harness/bin/pdf2md --schematic docs/sch/<板名>_sch.pdf

# 参数微调（图纸线宽/字号差异大时）
SCHEM_TOL=2.0 SCHEM_LABEL_TOL=6 bash features/.harness/bin/pdf2md --schematic <pdf>

# 对照实验：关掉图框剔除，看假网络是否增加
python harness/lib/pdf_schematic.py --pdf <pdf> --out /tmp/x.md --no-frame-guard

# 只转某几页
bash features/.harness/bin/pdf2md --schematic --pages 1-5 <pdf>
```

产物七节：图形统计 / 净网络 / 冲突网络 / 仅低置信名 / 未命名网络 / 孤立网络名 /
文字清单。第 2 节按**网名归组**（同一名字在图上的多个片段并列，注明页码/引脚/器件），
因为一个网络在 PDF 里天然是断开的若干段，按名字合并后才知道"这条信号去过哪些页、连了哪些脚"。检索优先用第 2 节和第 6 节（名字都在），拓扑结论只看第 2 节且必须抽查。

## 6. 何时不要用

- 有 `.SchDoc` / `.dsn` / `.kicad_sch` 源文件 → 直接导网表，精度不是同一个量级。
- 扫描件 / 位图 PDF（无矢量线段）→ 脚本会判「无矢量线段」并 exit 1，只可 `--ocr` 取文字。
- 需要用于改板、算电流、查短路 → 一律回原图。
